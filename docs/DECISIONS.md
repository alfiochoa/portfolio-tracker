# Decisions

Newest first. One entry per decision: what was chosen, over what, and why. Keep entries short.

## 2026-11-05: a NAV carried past Yahoo's last bar has no expiry; a Vanguard page that is an older view keeps the previous `vanguard` entry (builder-1, T-015; architect)

Seen live by T-012's builder: within a minute, Vanguard's page listed a fund's newest NAV and then omitted it. The merge rule now carries the previous file's value on every date after this run's first Yahoo bar that Yahoo lacks, after Yahoo's last bar included, so a NAV published once stays until Yahoo supplies the date (Yahoo's value then wins, unless Vanguard still lists it) or it falls off the six-month window; a date Vanguard later lists with another value takes Vanguard's. There is no expiry: an official NAV does not become false by being omitted from a cached page. For the file to change only in `generatedAt` on such a flap (so the scheduled workflow commits nothing), the fund's `vanguard` entry is kept when this run's page is an older view of the same data: its last date before the previous entry's `to`, every value it lists already in the file, and the previous entry's dates still in the bars with the same values; the entry then remains true of the file. Any answer that brings something new gets this run's entry. The script's printed lines still say what the page listed this run.

## 2026-11-05: the daily refresh is built for both homes before the owner has chosen; relative asset URLs; a commit only when more than `generatedAt` changed; the commit job does not wait for the deploy; the cron script builds even after a failed snapshot (builder-1, T-012; architect)

Where the refresh runs is Alfredo's decision (GitHub Actions with Pages, or cron on this machine), still open; both homes were built so that only the live step waits on him. The workflow follows market-desk's (`checkout@v4`, `setup-node@v4`, `upload-pages-artifact@v3`, `deploy-pages@v4`, the commit idiom), with these differences: it runs on a schedule (weekdays 08:15 UTC, after every fund has published the previous day's NAV) and by hand, never on push, so its own commit cannot start another run; each job declares the least permissions it needs; no secret exists or is read. The snapshot is committed only when more than `generatedAt` changed (`git diff -I`), so a holiday run adds no commit but still deploys, and the commit job depends on the build alone, not on the deploy, so the data is saved even while Pages is not yet switched on. `vite.config.ts` sets `base: './'` as market-desk does, so one build works at the root and under Pages' `/portfolio-tracker/` sub-path, with no build variable. The cron script (`scripts/refresh.sh`) never touches git, logs one line per step to `var/refresh.log`, runs one at a time (`flock`), and builds even after a failed snapshot run so the local page's badge says `run failed` rather than show yesterday's file as if nothing happened. If home B is chosen, the cron job should run from a separate clone, not the team's main checkout, which it would otherwise leave with an uncommitted data change every morning.

## 2026-11-05: npm audit: fflate updated; the minimatch advisory under eslint is accepted as dev-only (builder-1, T-014; architect)

`npm audit` on `main` showed one advisory in a runtime path, fflate's ZIP64 infinite loop (GHSA-px8p-9vwx-vf98), fixed by `npm audit fix` within the declared range (0.8.2 to 0.8.3; the import script is the only user, and fflate is not in the browser bundle). ## 2026-11-05: Vanguard's ten NAVs come from the product page's rendered table, anchored on the page's JSON state; a filled date stays filled (builder-1, T-011; architect)

Vanguard UK's product page is server-rendered: one GET returns the "Historical Prices" table (the last ten NAVs) and a JSON state (`serverApp-state`) that carries the fund's ISIN and only its latest NAV. The parser reads the table and checks it against the state: the ISIN must be the one asked for (a wrong ISIN in the URL still answers 200 with the id's fund, so the check is load-bearing) and the table's newest row must equal the state's latest NAV, which proves the right table was found and the markup still means what we think. The page's GraphQL endpoint was not used: undocumented, and it would mean a hand-written query. Merge rule per fund: this run's Yahoo bars, with the previous file's value carried on any date inside their span that Yahoo lacks (so a hole once filled from Vanguard never reopens after the date leaves Vanguard's ten, which the first rule as written would have allowed), then Vanguard's bars laid over (Vanguard wins on its dates). A Vanguard failure while Yahoo refreshed is a `warning` in the file and the badge detail's last line, with no change of state or colour: the numbers are complete and current, only those funds' newest days are unofficial. The first real run (2026-11-04 23:38 UTC) found Yahoo and Vanguard equal on all 72 shared fund-dates and filled 2026-10-26 for every fund; no window return moved.

## 2026-11-05: an open detail closes on `pointerup` outside it, not `click`; the snapshot parser refuses nonsense metadata; the page re-fetches when its tab is shown again (builder-1, T-010; architect)

The badge's detail closes on Escape (focus stays on the badge) and on a press outside the badge and its detail. The outside press is a document `pointerup` listener, installed once, rather than `click`: iOS Safari sends no `click` to the document for a tap on plain text such as a heading, and a touch that turns into a scroll ends in `pointercancel`, so scrolling past the badge does not close it. `parseSnapshot` now refuses a `generatedAt` that is not an ISO instant with a zone, a `state` outside `ok`/`partial`/`failed`, and a `source` without a string name, each with its reason, so the page shows ERROR for a file the script could not have written (the script's own read-back of the previous file goes through the same parser, and a refused previous file counts as absent, as a corrupt one already did). The snapshot fetch gives up after 15 s (`setTimeout` + `AbortController`, which Playwright's clock can advance; `AbortSignal.timeout` it cannot) and the page says so as an ERROR. When the tab becomes visible again the page fetches the snapshot again and judges it against the clock as it is now, so a tab left open overnight shows the day's state and a rebuilt snapshot without a reload; focus and clicks fetch nothing, and only the latest load's answer is rendered.

## 2026-11-05: the badge is a button whose text says every state in words; the run's own state is on it; its detail opens under it (builder-1, T-006; architect)

The badge's text is `NAV as of <L> · snapshot <time UTC> · <STATES>`, then ` · run partial` or ` · run failed` when the snapshot script's own run was not `ok`: a failed rebuild writes back the previous file, whose L can still be within two weekdays, so without that suffix a failed morning would read plain FRESH all day. The colour (`--ok`, `--warn`, `--error` tokens, both themes) is on the dot, the border and the state words, never alone: `ok` only for FRESH with nothing else; STALE, PARTIAL or a run that was not `ok` are `warn`; ERROR is `error`. Hovering shows the detail as the native tooltip; a tap, click or Enter opens it as a list under the badge (source, snapshot time in UTC and in the viewer's zone, the rule that applied, each fund's latest date when PARTIAL, the reason when ERROR, the script's recorded error when the run was not `ok`). "Today" for the two-weekday rule is the viewer's calendar date in their own time zone, the one place the viewer's zone matters; a Saturday or Sunday counts as the Monday after. The page renders at once in a `loading` state (allocation and positions as they are, the performance sections saying prices are loading) and again when the fetch settles. `vite.config.ts` sets `appType: 'mpa'` so dev and preview answer a missing snapshot with 404, as a static host does. `scripts/recompute.ts [--now <ISO>]` prints the badge and its detail with the instant and zone used, so the state is reproducible like every other number. The e2e fixture is FRESH · PARTIAL as it stands (one fund alone has 2026-10-26 inside the 2m window), which is kept: it doubles as the dropped-date case, and the FRESH/STALE tests use it with that bar removed.

## 2026-11-04: the chart is drawn at its own pixel width, with estimated text widths; a sparkline is the fund's own line; the readout is text above the chart (builder-1, T-005; architect)

A fixed `viewBox` scaled to a 328 px phone would shrink 12 px labels to about 6 px, so the SVG is laid out at the width its box has (`ResizeObserver`, redrawn on a change) and only scales between redraws. Label widths are estimated at 0.72 em per character (DejaVu Sans semibold digits measure 0.696 em; San Francisco's are narrower), which keeps `src/lib/chart.ts` pure and testable; the cost is a few pixels of margin. The y-scale pads the values by a twentieth and picks the smallest round step that needs at most five gridlines; 100 is always a gridline, drawn dashed. Month names give way to the end-date labels when they would touch (so "Nov" is usually dropped and its tick kept). A sparkline is the fund's own bars over the chart's window, a date the portfolio series dropped included, coloured and labelled by the fund's 2m cell so the two never disagree. The readout is a line of text above the chart, not a floating tooltip a finger would cover; it is reached by hover, tap and the arrow keys. A series shorter than two months is drawn from its first date (100 there) and the note under the chart says so. `scripts/recompute.ts` prints the chart's end value beside the windows, so the oracle covers the chart too.

## 2026-11-04: the page tells "no snapshot" from "unreadable" by the HTTP status: 404 is the former, everything else the latter (architect, from builder-1's T-004 report)

The spec names two states for a page without numbers: no snapshot yet (quiet placeholders) and snapshot unreadable (badge `ERROR`). The page fetches `data/prices.json` relative to itself; a 404 means the file is not there (no snapshot), and any other failure (a network error, another status, JSON that does not parse, a snapshot the definitions cannot compute from, such as a fund with no bars) is unreadable and logged to the console with its reason. The fetch is sent with `cache: 'no-cache'` so a snapshot rebuilt today is revalidated rather than served from yesterday's cache; the file is 35 kB, so the revalidation costs nothing worth saving. The page and `scripts/recompute.ts` share `readPrices` (parse, then compute), so a file the oracle refuses is one the page refuses, with the same reason.

## 2026-11-04: a Yahoo bar carries the NAV date; prices are read back as the shortest 32-bit float (builder-1, T-003)

Checked on all eight funds against Vanguard's UK professional product pages (`vanguard.co.uk/professional/product/fund/<equity|bond>/<id>/<ISIN>`, the last ten NAVs): 72 of 72 fund-dates equal, under the same date, so no shift is applied. Yahoo serves the prices as 32-bit floats (597.1246 arrives as 597.1245727539062); the parser writes the shortest decimal that is the same float, which restores Vanguard's four decimals exactly. A fund's `fetchedAt` is kept when a later run fetches the same bars, so a second run changes only `generatedAt`. The request's User-Agent is the bare `Mozilla/5.0`: full browser strings got 429 from this machine every time.

## 2026-11-04: Yahoo's missing 2026-10-26 NAV is accepted for now; Vanguard's own page becomes the second source in M2 (architect)

Yahoo has a null bar on 2026-10-26 for all eight funds although Vanguard published NAVs that day (US 500 €606.4686). ## 2026-11-04: the import keeps the export's own digits for each weight (builder-1, T-002)

`JSON.stringify` of the parsed double drops digits the export wrote (`9.0423422083395308E-2` became `0.09042342208339531`), so `data/portfolio.json` is rendered from the cell's text turned into plain decimal notation, digit for digit, with an assertion that it parses to the same double. "Unrounded" is then literally true and a re-import of the same export is byte-identical. `fflate` is a devDependency (only the script uses it; a test walks the page's import graph to prove it stays out). The test fixture is the export's XML parts zipped in memory, not a committed binary.

## 2026-11-04: prices come from Yahoo Finance's chart endpoint; Twelve Data only if a probe shows the free plan serves fund NAVs (architect)

The eight funds are Irish UCITS mutual funds, not ETFs. Twelve Data knows the exact share classes (`0P00011HBK` etc., Frankfurt) but its pricing page lists "Mutual funds NAV" under the Pro plan ($229/month), so the free key Alfredo offers very likely returns an error for them. Yahoo Finance's keyless chart endpoint (`/v8/finance/chart/0P00011HBK.F`) returned 65 daily EUR NAVs per fund for the last three months, checked for all eight on 2026-11-04. Chosen: Yahoo as the primary source (labelled unofficial on the badge, previous file kept on failure), one 1-credit Twelve Data probe in M1 to decide whether it stays as a fallback. Alternatives considered: proxy US-listed ETFs converted to EUR on the free Twelve Data plan (approximate, no match for the bond funds), scraping Vanguard's own site (no documented endpoint found), Morningstar's timeseries API (returned nothing).

## 2026-11-04: Vite + TypeScript, vanilla DOM, own SVG charts, fflate for the export (architect)

Same stack as market-desk so one person can keep both; no framework for one page; no chart library for one line, eight sparklines and a bar; `fflate` plus a minimal SpreadsheetML reader instead of SheetJS (the export is one sheet of three columns).

## 2026-11-04: the portfolio is a buy-and-hold of the exported weights, anchored on the export date (architect)

The export gives weights only. The value index `V(t) = Σ w_i · P_i(t)/P_i(T)` backs out the start-of-window values from today's weights, which is what "how did my current portfolio do over the last month" means; fixed-weight (daily rebalanced) returns were the alternative and would overstate nothing for short windows but are not what he holds. Exact definitions in `docs/SPEC.md`.

## 2026-11-04: the export is gitignored; `data/portfolio.json` (weights only) is committed (architect)

The product cannot run without the weights, and they are the least sensitive thing about a portfolio (no amounts, no identifiers); the `.xlsx` is a personal binary export that changes on every download. If the repository is ever made public (deploying to Pages, the owner's decision), the weights are visible on the page anyway.
