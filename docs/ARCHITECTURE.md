# Architecture

The stack and the rules that hold everywhere. `docs/SPEC.md` says what is built; this says how. The architect keeps it true.

## Goals

Static hosting, no backend, no secret in the browser, the same shape as market-desk so that whoever knows one knows the other: a snapshot script fetches the data with whatever key it needs, writes JSON files, and the site only reads them. Every number on the screen can be recomputed from the two data files by a script.

## Stack

- **Vite + TypeScript**, vanilla DOM (no framework): one page, a handful of components, as market-desk. `npm` and a committed `package-lock.json`. Node 24 runs the scripts as TypeScript directly (type stripping): `node scripts/build-snapshots.ts`.
- **Charts**: inline SVG drawn by our own code (the `dataviz` skill's rules), no chart library: a line, sparklines and a bar are not worth 75 kB.
- **Checks**: `tsc --noEmit`, ESLint (typescript-eslint), vitest for units; Playwright for the smoke run, Chromium with `chromiumSandbox: true`.
- **Dependencies**: as few as possible. `fflate` to unzip the `.xlsx` (a zip of XML; we read one sheet with our own small parser rather than pull SheetJS). Nothing else at runtime.
- **Secrets**: `.env` at the repo root, gitignored, read only by the snapshot script through Node's `--env-file`. The browser bundle never sees it; a test asserts no `api.twelvedata.com` or key string in `dist/`.

## Structure

```
index.html                 the one page's shell
src/main.ts                boot: data/*.json bundled at build time, public/data/prices.json fetched at runtime; compute, render
src/lib/                   pure, unit-tested, no DOM:
  portfolio.ts             the catalogue and allocation types, positions joined to the catalogue, equities/bonds split
  returns.ts               portfolio series, value index, the five windows (SPEC "Exact definitions")
  freshness.ts             badge state from a snapshot and a clock
  format.ts                percentages, dates, signs
  xlsx.ts                  the minimal SpreadsheetML reader for the export
  yahoo.ts                 parser for the chart endpoint's JSON into bars
  twelvedata.ts            (M1, if the probe succeeds) parser and credit rules
src/ui/                    rendering, one file per section: badge.ts (header), tiles.ts, chart.ts, positions.ts, allocation.ts, footer.ts; dom.ts is the element builder (text as text, never innerHTML)
src/styles.css             tokens on :root (and the dark/light overrides), then components
data/funds.json            the fund catalogue (hand-maintained, committed)
data/portfolio.json        the allocation, generated from the export by scripts/import-portfolio.ts
public/data/prices.json    the snapshot, generated by scripts/build-snapshots.ts (committed as the baseline)
scripts/import-portfolio.ts   xlsx -> data/portfolio.json
scripts/build-snapshots.ts    sources -> public/data/prices.json
scripts/recompute.ts          prints what the page should show, from the two data files (the verifier's oracle)
tests/                     vitest, one file per src/lib module and per section; fixtures under tests/fixtures/
e2e/                       Playwright smoke: the built site, network mocked, every section renders with its state
docs/                      SPEC, ARCHITECTURE, DESIGN, DECISIONS, CONVENTIONS
```

## Data model

`data/funds.json`: the catalogue.

```json
[{ "id": "us500",
   "name": "Vanguard US 500 Stock Index Euro - Institutional Plus",
   "shortName": "US 500",
   "isin": "IE00BFPM9V94",
   "kind": "equity",
   "assetClass": { "es": "Acciones Estados Unidos", "en": "US equities" },
   "sources": { "yahoo": "0P00011HBK.F", "twelvedata": "0P00011HBK",
                "vanguard": { "kind": "equity", "id": "9186" } } }]
```

`name` is the match key for the export, character for character. Adding a fund Alfredo's advisor might use is a one-entry change here.

`data/portfolio.json`: the allocation. Weights are the export's values, unrounded.

```json
{ "anchorDate": "2026-11-04",
  "sourceFile": "distribucion_agregada_cartera.xlsx",
  "positions": [{ "fund": "us500", "weight": 0.3983588675690416 }, ...] }
```

`public/data/prices.json`: the snapshot. Bars are `[date, nav]`, the date the NAV date, ascending, no nulls.

```json
{ "generatedAt": "2026-11-04T21:40:00Z",
  "source": { "name": "Vanguard (official) + Yahoo Finance (unofficial)", "kind": "vanguard+yahoo" },
  "state": "ok",
  "funds": { "us500": { "currency": "EUR", "fetchedAt": "...",
                        "vanguard": { "fetchedAt": "...", "from": "2026-10-21", "to": "2026-11-03", "bars": 10 },
                        "bars": [["2026-08-04", 591.88], ...] } } }
```

`state` is `ok`, `partial` (some funds kept from the previous file; each such fund carries `kept: true` and `error`, and the file a top-level `error` listing them) or `failed` (nothing fetched; the previous file is written back unchanged with the new `state` and `error`). A fund's `fetchedAt` is when its bars were fetched; a run that gets the same bars again keeps it, so a second run changes only `generatedAt`. The file has one bar per line, so a daily refresh is a short diff.

Each fund's bars are Yahoo's six months (or, when Yahoo failed, the previous file's, `kept`) with the last ten NAVs of Vanguard's product page (`vanguard.co.uk/professional/product/fund/<kind>/<id>/<ISIN>`, `src/lib/vanguard.ts`) laid over them: on a date both have, Vanguard's value; a date Yahoo lacks, inserted. The fund's `vanguard` entry says which dates came from Vanguard (`from` to `to`, `bars` of them, every one of Vanguard's ten) and when they were fetched, or `{ "error": "..." }` when the page could not be read; files from before M2 have no `vanguard`, and `parseSnapshot` reads them. `state` follows Yahoo: a Vanguard failure on an otherwise `ok` run is a top-level `warning` naming the funds, and the run is `failed` only when no fund got bars from either source.

## Rules that hold everywhere

1. **The browser reads files, never APIs.** All fetching is in `scripts/`. No key, no third-party call, from the page.
2. **Pure logic in `src/lib`, tested with fixtures.** Dates and NAVs in tests are literal; no test calls the network (a vitest setup makes `fetch` throw), and no test names a path on this machine.
3. **One freshness model.** Every section takes its state from `src/lib/freshness.ts`; no section invents its own "stale".
4. **Exact definitions live in one place**, `src/lib/returns.ts`, and `scripts/recompute.ts` uses the same functions, so the oracle and the page cannot disagree by construction; the verifier compares both with a hand calculation for one window.
5. **Fail closed, keep the previous file.** A snapshot run that cannot fetch leaves the last good data in place and says so in the file; it never writes an empty or partial file silently.
6. **Tokens, not literals.** Colours, type sizes and spacing are CSS variables on `:root`, overridden per theme; components use the variables. `docs/DESIGN.md` names them once the direction is chosen.
7. **Dates are ISO strings (`YYYY-MM-DD`) end to end**, compared as strings; NAV dates have no time zone. The only clock is `now` passed in as an argument (freshness, window boundaries), so tests fake it.
8. **Nothing about Alfredo's money in the repository** beyond the weights: no amounts, no account identifiers. The export file itself is gitignored; the typed total (M2) stays in `localStorage`.
9. **Scripts are idempotent** and safe to run twice; they print what they did and exit non-zero on failure.
